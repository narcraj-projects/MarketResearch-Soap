# Four-minute Lather Lens walkthrough

The final MP4 is a four-minute captioned walkthrough with an offline Windows-generated synthetic voiceover, explicitly selected by the user. You can record your own voice using the same script. It inspects the saved 26 October LIVE sample and starts no new paid run. The last 30 seconds explain the architecture.

| Time | Show | Narration |
| --- | --- | --- |
| 0:00-0:25 | Brief | Lather Lens is a market-research application for a handmade-soap founder. We are researching competitors in India to understand their products, listed prices, ingredients, positioning and sales channels. The purpose is to help the founder make better product and marketing decisions using evidence rather than guesses. This project uses Petite Batch's market brief as its research scenario. |
| 0:25-0:55 | Shortlist | The Scout uses Tavily to discover competitors and a model to assess relevance. Source identity and geography checks run in code. Fika Soaps and Forest Essentials passed the checks and the user approved this two-brand shortlist. The system did not invent a third company just to fill a quota. Each candidate links back to its search evidence. |
| 0:55-1:25 | Live Run | LangGraph is the orchestrator. It routes the workflow through validation, discovery, human review, independent competitor research, normalization, analysis, review and final approval. Postgres retains events, checkpoints and completed work. Research failures do not silently become facts. The pilot recovered from provider errors and a citation validation issue using its saved state. |
| 1:25-2:00 | Report briefing | Researcher agents collect public web and news evidence, while the Analyst drafts attributed notes and conditional strategy. A separate Reviewer checks evidence, dates, arithmetic and unsupported wording. The pilot uses Fireworks provisionally through a provider-neutral adapter. It is not a benchmark winner. The quality benchmark is designed but final model selection remains open. |
| 2:00-2:30 | Comparison | The comparison now displays Fika's persisted source-attributed prices and ingredient notes, with clickable evidence. These were already present in the approved briefing; the earlier display showed only structured extraction. Notes remain labeled source claims, not verified SKU facts. The application requires a matching SKU, price, pack and weight before calculating price per one hundred grams. Incomplete bindings remain unknown. Unsupported opportunity premises were removed rather than called a proven market gap. |
| 2:30-3:00 | Sources/review | Every retained source has its URL, retrieval time, excerpt and hash. A working citation proves traceability, not genuine support for every statement. The independent model reviewer caught incorrect price framing and date summaries. Corrected version four uses conservative attributed wording. Human claim adjudication and business-owner usefulness scores are still unmeasured, and the report makes those limits visible. |
| 3:00-3:30 | Approved report/export | The user explicitly approved corrected report version four. Approval binds the exact version and content hash; the worker then saved the immutable report. HTML and CSV exports are available. This completes the demonstrated local workflow. The source, illustrated overview, walkthrough and sourced sample form the submission. No hosting, deployment or external publishing is needed to demonstrate the project. |
| 3:30-4:00 | Architecture | Technically, the interface uses Next.js, TypeScript and Tailwind. Python FastAPI validates the application API. LangGraph coordinates the agent workflow. Supabase Auth and Postgres store owner-scoped evidence, checkpoints and approvals. Tavily supplies search; a provider-neutral adapter connects the provisional Fireworks model. Pytest, Vitest and Playwright support testing and screenshots. LangSmith integration is available, with remote export disabled. |

If asked about agents versus models: Scout, Researcher, Analyst and Reviewer are logical roles that use LLM calls. The LangGraph orchestrator, security checks, budgets, arithmetic, persistence and approval enforcement remain deterministic code. Offline golden fixtures are explicitly DEMO and are evaluated separately from the real-source sample.
