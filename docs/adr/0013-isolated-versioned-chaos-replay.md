# ADR 0013: isolated immutable DEMO plans and exact replay

Status: implemented for B12 review. Date: 25 October 2026.

The PRD recovery demonstration and HTML Chaos switches must exercise actual harness/worker behavior while preserving the BRD's attribution, partial-state recovery, honesty and approval requirements. Production must reject fault injection. The user's quality-first/provider-neutral decision and prohibition on paid calls/deployment remain binding.

Choose an immutable allowlisted `chaos-1.0` plan on a **new** DEMO run, pinned to a manifest and checked by API, worker and model replay gateway. Require server environment=test, explicit flag, replay-only mode and dedicated local database address; the CLI additionally checks database identity. Client flags and arbitrary response/path/URL/existing-run input cannot grant authority. The browser renders controls only after server capabilities; same-origin/auth/idempotency rules are unchanged. Production refuses configuration, HTTP injection and persisted test jobs before tool dispatch.

Use exact versioned response tapes plus existing per-attempt journals. A resumed cached failure advances the replay cursor without dispatching/charging twice. Parallel operations remain independently deterministic; global timing/interleaving is not canonicalized. Model templates are labeled synthetic frozen rule-output projections with no actual provider/model calls, quality score or model selection.

Use real retries, JSON validation, independent mechanical review and Postgres checkpoints. The only process kill callback belongs to a separately launched test CLI after an actual durable lane commit. A fresh process recovers after the real lease expires; the server never exposes a kill endpoint. Production and uncertain-attempt paths fail closed. Preserve unresolved gaps rather than manufacturing successful extraction/report values.

Repeated execution found that LangGraph may submit pending writes before the parent checkpoint transaction commits. Preserve the foreign key and immutable checkpoint payload: wait for the actual owner/fenced parent outside database locks, bounded to five seconds, then recheck the lease before writing. Condition notification is an optimization only; a fresh process checks Postgres. A missing parent produces a policy stop, never a placeholder/orphan checkpoint. Deterministic concurrent ordering and missing-parent tests cover the fix; no graph schema or migration changes.

Consequences: the reference's toggles become nine accessible radio choices and a separate-run action, retaining its amber control-room panel. Arbitrary fault combinations/mid-run mutation need new reviewed fixtures and are excluded. No new migration/dependency or graph pin is needed; the optional plan/replay schemas version their own meanings. The old narrow prototype Event/FaultConfig are not public injection authorities or durable-event validators. A future incompatible replay payload requires a new schema/dataset pin. Full semantic quality, model benchmark, BRD five-failure cohort and live acceptance remain separate, unmeasured work. Stop for review; no subsequent stage automatically.
