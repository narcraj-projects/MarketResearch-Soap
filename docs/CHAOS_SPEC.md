# B12 deterministic replay and isolated chaos

Scope: the nine requested failure switches, replay boundaries, durable recovery and truthful Live UI. BRD business requirements and exact acceptance targets remain authoritative; the original HTML controls the visual composition and PRD v1.1 proposes implementation. No subsequent stage, live provider, paid benchmark, telemetry, provisioning, publishing or deployment is authorized by these changes. Inputs remain the readable, unchanged originals and their previously authorized aliases.

## Plan and requirements

Use the existing harness, owner repositories, attempt journal, leased LangGraph worker and two approval interrupts. Add the smallest independent test plan to a new DEMO run; choose pinned responses at the tool/model boundary rather than making UI outcomes. Keep completed lane rows, sources, hashes, checkpoints and usage through restart. Validate inputs/versions, bound attempts/budgets/deadline, persist actual failure/recovery events and show both resolved and unresolved states. Refuse production injection before dispatch. The provider-neutral quality benchmark remains a prerequisite to selecting actual models.

## Trust boundary

`Settings` accepts `local`, `test` and `production`; default is local. `chaos_enabled` defaults false and cannot be true outside test. API, worker and model replay gateway require test + explicit server flag + replay mode + external calls disabled. API/worker/model gateway require a database engine at exact `127.0.0.1:57422`. The dedicated worker/demo CLI additionally validates local Auth port 57421, both database URLs and the database identity marker through `local_config`. This is a local test facility, not a hosted production feature.

Authenticated `GET /api/chaos/capabilities` returns disabled/empty unless the server gate and database address permit it. Authenticated `POST /api/chaos/runs` accepts only an allowlisted scenario and an idempotency key. It transactionally creates its own DEMO brief/run and queues a versioned plan. It accepts no existing run ID, raw response, fixture path, URL, approval, server environment or authorized flag. Same-key/same-body replay returns the same run; changed body conflicts. Cross-owner reads remain hidden by Auth/owner predicates/RLS. The BFF enforces same origin, session and key, with a fixed upstream path and no-store responses. A client flag cannot enable the backend.

The API does not execute a worker or terminate a process. Only `python -m tools.chaos_worker` supplies the interruption callback, after all server/local identity gates. The callback exits that dedicated worker with code 23 after an actual lane commit. Production configuration rejects the flag, production API rejects injection, and a production worker refuses even a persisted test plan before tool attempts. Server configuration is trusted operator input; this does not attempt to defend a production process whose operator deliberately mislabels its environment and reconfigures it as the isolated local test stack.

## Replay contracts

`harness/replay.py` defines frozen, extra-forbidden `ReplayRequest` and `ReplayStep`, schema `replay-1.0`. A request binds response kind (search/model/tool), logical operation, attempt, exact arguments and graph/provider/model/prompt/tool/dataset versions. Responses carry SHA-256 and DEMO label. `ReplayTape` checks hash at construction, rejects duplicate/noncontiguous steps, rejects wrong arguments/versions/extra operations, enforces per-operation attempt order and fails unfinished tapes. Re-reading an identical step is stable. Independent lanes may interleave differently; wall-clock timestamps, database IDs and global event interleaving are not promised byte-identical across runs. There is no live fallback.

Existing search and public HTTP/DNS wire recordings remain the concrete tool replay adapters. Search maps the exact canonical request plus attempt to a pinned step. The persisted attempt journal supplies earlier results after restart; `observe_cached` consumes those logical steps without redispatch or double accounting. Public retrieval similarly selects the correct retry slot and advances cached DNS observations. This fixes restarting after a recorded failure accidentally replaying attempt one or resetting DNS state. Unknown request/response/version/hash fails closed.

`chaos-demo-v1` pins a SHA-256 manifest for the scenario registry, search/web recordings and model templates. `ChaosPlan` schema `chaos-1.0` stores that manifest hash with the job. Every worker verifies the pin; editing fixtures cannot silently alter a pending run. Base search/public-web fixture schemas retain their existing `scout-demo-v1`/`research-demo-v1` versions. No graph-version bump or database migration is required: the optional child plan is explicitly versioned and normal workflow-1.2 options remain exact.

Model replay is provider-neutral and offline. It binds a frozen rule-analysis input hash and versioned prompt/tools to raw recorded JSON. The checked-in model templates are **synthetic frozen rule-output projections**, including malformed text and an arithmetic defect; they are not captured outputs of any real provider. No model is selected, evaluated or invoked. The gateway validates the complete `AnalysisDraft` handoff, journals raw response/hash privately in owner-protected attempt outcomes and emits only hashes/version/error codes to events. Generic tapes can carry captured provider-neutral raw responses later, but capturing a real model response still requires separate authorization and benchmark work.

Model replay revalidates RunContext, lease owner/run, current run version/status, actual persisted shortlist decision/hash, deadline and tool/phase permission. Before each new attempt it locks the run, checks shared completed/reserved call counts, tokens/cost and reserves an attempt. Replay usage counts fixture handoffs, with actual model calls/tokens/cost zero. The max-output token preflight (16384) is a bound, not measured token consumption or an implemented paid-provider token reservation scheme. Completed responses replay without duplicate usage. An uncertain reserved model attempt stops conservatively; it is not silently refunded or dispatched again. Generic paid-model execution remains absent.

## Nine allowlisted scenarios

| Scenario | Injected recorded boundary | Expected real workflow outcome |
| --- | --- | --- |
| timeout | First search times out; next succeeds | Two attempts, one persisted retryable failure and recovery, real shortlist review |
| rate_limit | Search 429 then 200, recorded Retry-After | Same bounded retry path and actual recovery; existing deadline/delay negative tests remain active |
| empty_results | Both bounded discovery queries return no candidates | Partial stop, zero invented competitors/reports, visible lack of evidence |
| inaccessible_page | One product page returns 403 | No bypass/retry of denied page; source status and missing product fields persist; other lanes survive |
| conflicting_price | Two scoped offers for the same item disagree | Both amounts (DEMO 120/160 INR) and conflict survive, no arbitrary preferred price |
| missing_weight | A retrieved price has no weight | Raw price persists; per-100g stays null, never guessed |
| malformed_json | Invalid raw JSON then valid frozen analysis | Schema failure event and one repair; terminal-invalid and budget-exhausted variants stop without report fabrication |
| reviewer_rejection | Typed analysis contains wrong unit arithmetic | The real independent mechanical Reviewer requests one targeted revision; corrected immutable v2 is reviewed before final approval |
| interrupted_worker | Process exits after one committed research lane | Lease expires, fresh process reclaims job, reuses the identical task/source hashes and executes only remaining two lanes |

Wire retry limit is three total attempts. Model schema repair limit is one additional attempt (two total). Reviewer revision limit remains one. All respect existing call/cost/deadline/cancellation and fencing checks; a successful fixture does not override an approval. Empty/denied/conflicting/missing evidence are honest outcomes, not errors to erase until a green indicator appears. Model-output fault fixtures exercise the same typed analysis/review boundary; they do not prove strategic semantic quality.

## Events, state and UI

Repeat-run verification also exposed an actual parent/pending-write ordering race: LangGraph can submit `put_writes` before the background parent `put` commits even with synchronous step durability. `OwnerPostgresSaver` now waits up to five seconds for the owner/run-scoped durable parent, without holding run/job locks between checks. A post-commit condition notification reduces delay; the database remains authoritative after process restart. Lease/fence checks apply on each check and the final write. Missing parents fail closed with `checkpoint_parent_not_durable`; no placeholder checkpoint, orphan row or relaxed foreign key is introduced. CI06 forces writes-before-parent deterministically and verifies a fresh saver/idempotent reuse; CI07 verifies the bounded missing-parent refusal. The existing payload, graph pin and migration remain unchanged.

Existing persisted `EventRecord` is the owner-scoped ordered durable envelope consumed by polling/SSE. It accepts additive kind strings, unlike the earlier narrow prototype `harness.contracts.Event`; the prototype is not the persistence serializer. New kinds are `chaos.armed`, `chaos.plan_loaded`, `chaos.observed`, `chaos.research_observed`, `chaos.worker_interrupted`, `chaos.worker_recovered`, `model.replay_reserved`, `model.output_invalid`, `model.replay_validated`, `tool.retryable_failure` and `tool.recovered`. Job plan/replay request supply explicit version pins. These additive kinds do not change old payload meanings or cursor order; incompatible payload meanings require a new kind/schema version.

`chaos.armed`/`plan_loaded` mean configuration verified, not failure occurred. Retry events are committed with actual completed attempt outcomes; recovery means an actual later successful attempt. Model invalid/validated events follow actual Pydantic parsing. Worker reclaimed is emitted by the existing lease transaction; preserved lane recovery follows real task reuse. No scheduled success event or client counter pretends work happened. A crash between committed outcome and a subsequent summary event can omit that summary; durable outcomes remain authoritative and an uncertain attempt fails closed.

Workspace exposes validated plan metadata and aggregate event counts across the **entire** run, independent of the terminal's latest-100 window. Live keeps the reference control-room composition, forest/lime/competitor colors and dashed amber chaos panel. Nine native radio controls choose one scenario for a separate DEMO run. This deliberately resolves the prototype's mutable five toggles into immutable server-pinned single-scenario plans; arbitrary combinations would need separately versioned fixtures. Failed queuing shows an error and keeps the current run. Queued runs show no completed lanes/recoveries. Saved events, nulls, partial lanes and final approval state drive the UI after reload. Keyboard focus, reduced motion and responsive width checks remain active.

Citation presence counts a link, quote integrity checks that an excerpt/hash matches, and genuine support requires independent trusted semantic adjudication of proposition, attribution, SKU/pack/date, relevance, contradictions and inference. A quote can be intact but fail support. These DEMO fixtures and rule Reviewer never set genuine-support coverage; it remains null. All material factual assertions, including uncited/unsupported ones, stay in the denominator; an empty denominator is unavailable, not 100%. Owner usefulness is also unmeasured.
