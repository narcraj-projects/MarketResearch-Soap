## Graders and baseline

`app/evaluations/graders.py` independently grades typed persisted schema/hash, Decimal arithmetic and declared same-SKU/null expectations, provenance-backed candidate identity/no quota invention, tool allowlists, exact-replay argument enforcement, typed unique bounded attempt journals and workflow partial orders. Approval grading joins actual durable request/decision rows, checking hashes/versions rather than trusting an event's claimed decision. Parallel sibling event ordering and wall-clock timestamps are not exact-match oracles. Missing or unrecognized assertions cannot silently pass. Case-specific checks expose intermediate evidence/fault outcomes, including repeated invalid JSON and preserved state.

The proposed baseline records a separate actual all-pass execution. It is never written over an existing baseline or promoted automatically. It binds dataset/manifest/grader and execution versions, normalized critical implementation hashes, case membership, grader results, trajectory/call signatures and observed measurements. A second independent run compares against it. Changed versions, missing cases, critical grade/trajectory/tool/budget signatures fail comparison; latency/token/cost deltas are reported. No invented latency threshold or cost-weighted quality ranking is introduced. Initial baseline status is `pending_user_review` until the user reviews it. Strict deterministic CI may use its pinned expectations, while release remains blocked on baseline review and missing business evidence.

All required deterministic safety/math/schema/permission/approval/recovery checks must pass even when A05 reaches four of five. Unknown human or semantic gates never become a pass. `--release-check` remains blocked for this synthetic-only suite, with explicit blockers; `--live` is rejected before provider execution. Paid/live benchmarking follows MODEL_BENCHMARK.md under a separately approved provider/profile and budget, outside push/PR CI.

## Citation integrity versus support

Citation presence counts attached links for **all non-null fact/source-claim findings**, including unsupported/uncited assertions. Unknown notices are excluded only when no product fact is asserted. Hypotheses/interpretations do not hide their factual premises; those premises remain material findings. Zero material denominator is unavailable, never 100%.

Quote integrity additionally checks resolved same-report source, usable access, exact excerpt membership and quote hash. Neither presence nor integrity establishes entailment, relevance, correct attribution, currentness, item scope or the complete proposition. D12's wrong assertion has a valid, irrelevant quote; deterministic review must reject it. The report separately shows presence/quote diagnostics and **unmeasured** genuine-support coverage.

`GET /api/runs/{run}/review-packet?report_id={id}` returns an owner-protected typed packet bound to immutable report and statement hashes, source dates/hashes/excerpts and all material assertions. Claims keep their original agent-unreviewed status. A trusted human must check every atomic component, relevance, attribution, date/freshness, SKU/variant/pack/currency, contradictions and medical scope. The reviewer records supported/contradicted/insufficient plus rationale and personal attestation.

`POST /api/runs/{run}/claim-reviews` accepts only an authenticated owner explicitly granted in server `LATHER_TRUSTED_REVIEWER_IDS`. `POST .../owner-ratings` additionally requires `LATHER_BUSINESS_OWNER_IDS`, a saved approved exact report, useful/not-useful, five rubric comments and an owner attestation. Both require idempotency keys; stale hash/statement, foreign source/report/owner, invented reviewer identity and missing checks are rejected. Role grants default empty; client labels cannot grant authority. Receipts are append-only in existing evaluation tables under runtime UPDATE/DELETE denial; reports themselves are unchanged.

`purpose=demo_fixture` is allowed only under isolated evaluation gates and never counts as actual human evidence. Acceptance aggregators require durable owner-scoped receipts, server-granted reviewer identities, exact report/statement binding and human purpose; bare JSON/golden/model labels cannot self-certify support. Partial adjudication is explicitly incomplete, with a confirmed lower bound only; final support coverage/gate requires complete adjudication. The owner cohort is predeclared as D01/D02/D07/D08/D11, resolved to five distinct exact saved reports before ratings. Zero or fewer-than-five real ratings is not evaluated, not zero usefulness and not a substitute score. A real person's judgment and identity cannot be proven by schema tests; actual reviews remain necessary.

## Metrics and LangSmith

Each evaluated run stores measured monotonic local latency, aware UTC boundaries, completed/reserved calls, recorded model handoffs, actual provider-token scope and cost upper bounds. Virtual retry delays are recorded separately; they are not reported as live latency. Unknown accounting after execution failure is null. Replay token counts are zero because no model was called; they are not tokenizer estimates or claims about a model's efficiency. Local wall latency includes database/worker startup/recovery and scripted fixture approval overhead, not human deliberation or hosted performance.

Sanitized local traces are `sanitized-trace-1.0`: opaque per-batch trace IDs, fixed case/version/provider/model/prompt labels, whitelisted node/tool names, attempts, timestamps and measured counters. No owner IDs, raw run IDs, queries, URLs, briefs, prompts, model bodies, source text, raw errors, review notes, credentials or arbitrary metadata are included. Completion events are represented as timestamped event points, not invented node-duration measurements. The real pinned LangSmith SDK is tested with an in-memory HTTP session and canary secrets; no network request is sent in CI.

Remote export is a separate explicit CLI. `LATHER_TRACE_ENABLED`, `LATHER_TRACE_EXPORT_APPROVED`, a private API key, **existing** project UUID and approved `LATHER_TRACE_MAX_RUNS` are all required; endpoint and payload fields are allowlisted. The complete batch is checked against the run cap before any send. No project/dataset creation is performed. SDK automatic batching/runtime metadata/prompt cache are disabled; main app automatic tracing remains disabled. No remote export was executed in this stage. `.cache/evaluation-review-packets.json` contains private review material and is excluded from trace/CI artifacts.
