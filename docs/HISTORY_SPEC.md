# B11 immutable history and evidence comparison

25 October 2026. Implemented locally, pending user review. This stage implements FR-09 repeat research/history with FR-03/04/07 provenance and FR-08 approval boundaries. It does not start B12 or any later stage. All original source inputs were read and remain unchanged: seven-page BRD including its exact acceptance table and XML notes/footer (no embedded objects), PRD v1.1, and all five decoded HTML templates/styles/interactions. Original approved filename aliases still apply. No live API, paid model/search call, publishing, competitor contact, deployment or cloud provisioning.

## Plan and requirement decisions

1. Reuse immutable report rows and owner isolation; add exact version reads and paginated metadata without rewriting old artifacts.
2. Compare only two distinct, chronologically ordered, approved/saved report snapshots with matching category, geography and customer. Preserve dated sources and uncertainty. Never read current competitor/product values into historical findings.
3. Derive versioned stable brand/product identifiers from captured identity inputs, not per-run row IDs or fuzzy names. Compare facts and attributed source claims only; do not diff strategic hypotheses into market facts.
4. Retain Claude's forest/lime history cover, timeline, counters, competitor colors and before/after cards. Add explicit run/version controls, filters, exact-version links, evidence dialogs and real empty/loading/error behavior.
5. Validate with versioned DEMO golden cases, real dedicated local Auth/Postgres tests and responsive desktop/mobile browser checks. Record actual results and stop for review.

BRD FR-09 requires saving previous reports and distinguishing past information from current findings. PRD Journey C explicitly prohibits treating missing retrieval as discontinuation. The HTML's example Gone/Not found on re-check is weaker evidence than the BRD permits. Resolution: preserve the composition; qualify Gone as a first-party source explicitly reporting discontinued for an established matching SKU. A missing page, denied access, changed shortlist, missing field or absent search result is unknown/stale. New means newly observed in the selected evidence sample, never a proven market entry/launch. Counts are field observations, not a product/brand/launch total. These choices are explicit interpretations, not edits to the source documents.

PRD proposes reports and report_versions tables. Existing reports already provide unique (run_id, version), immutable JSONB/hash and SELECT/INSERT-only runtime grants with FORCE RLS. A second duplicate versions table would split the approved artifact. Reuse this existing version store; no migration, dependency/lock change, report backfill or historical rewrite. Existing rollback/reapply checks remain required. See ADR 0012.

## Contracts and APIs

`history_types.py`: frozen HistoricalVersion, VersionList, DatedEvidence, HistoricalValue, HistoricalChange and HistoryDiff. Response schema history-diff-1.0; identity policy history-identity-1.0. Each change carries stable brand/product IDs, field, status, reason, epistemic kinds, both captured value sets, source URLs/retrieval dates/status/content hashes, exact excerpts/quote hashes/locators and caveats. Counters enumerate new/changed/gone/unchanged/unknown/stale. Color follows the later report's competitor order, with earlier-report fallback for an unmatched earlier selection.

- GET /api/runs/{run_id}/versions?limit=100&offset=0: owner-protected immutable version metadata, exact hashes/dates/approval state, comparable flag and true total. Unapproved/revised drafts remain readable; only approved saved snapshots compare. Invalid-digest legacy siblings list integrity_error/noncomparable without hiding valid versions or exposing corrupted contents.
- GET /api/workspace?run_id={UUID}&report_version={positive int}: read that exact version; no fallback to the latest if absent or malformed. Existing default behavior remains for requests without a version. /report?run={UUID}&version={int} preserves exact selection across reload. Invalid/cross-owner versions fail 404; malformed requests fail 400/422; integrity failure is 409.
- GET /api/history/view: existing paginated run archive adds report-version count and exact approved saved version. Metadata includes the saved evidence as_of separately from run creation and does not infer product changes.
- GET /api/history/diff?before_run={UUID}&after_run={UUID}&before_version={int}&after_version={int}: checks both run owners before loading content; checks exact versions/hashes/presentation bindings; rejects drafts, same/reversed runs, incompatible scopes and undated reports. The result is read-only and deterministic from frozen input, never wall-clock dependent or persisted as an updated report.

All routes use existing verified Supabase Auth/non-bypass owner transactions. Next BFF retains HttpOnly session credentials, explicit path/query allowlists, sanitized errors, redirect denial, no-store responses and bounded upstream timeout. There is no new public write route, service-role frontend credential or external tool. Approval/export gates remain intact. Report projection additionally clears an invalid/mismatched presentation and checks run/brief/owner binding; a failed validation cannot accidentally leave a parsed snapshot exportable.

## Stable matching policy

Brand ID = namespaced UUIDv5 of exact IDNA/lowercase host (common www prefix removed) plus NFC/casefold/whitespace-normalized captured brand name. Scheme, product-page path, fragments and tracking parameters do not change brand identity. Distinct names on one host are not merged; separate subdomains remain separate. This is an evidence identity convention, not independently verified legal/business ownership. Rebrands, domain changes and ambiguous marketplace identities require reviewed aliases before live use; no alias is invented.

Product ID = UUIDv5 in that brand namespace of exact case-sensitive trimmed NFC SKU and literal variant (including null). Run-local competitor/product/source IDs and display product names never drive a match. Same SKU in different brands or variants remains distinct. Missing SKU/brand identity produces an explicit unmatched unknown row with available dated evidence; no fallback based on similar names, price, array position or a guessed identifier. The algorithm/version is explicit; future matching changes require a separately versioned policy/evaluation rather than silently changing these IDs.

Snapshot analysis supplies product-locator to SKU/variant mapping through its normalized-price observations, including ineligible/missing-price records. A SKU-less extraction stays unknown. Brand identity comes from the frozen selected shortlist. The diff reads ReportSnapshot only, not mutable live competitor/product tables or new retrievals.

## Evidence eligibility and statuses

Compare supported non-null fact/source_claim observation sets. Exact excerpt membership, quote SHA-256, source presence, competitor scope, accessible page evidence and captured dates must validate. Multiple disagreeing known values stay conflicting/unknown; no silent averaging or latest-source selection. Unknown/uncited/malformed evidence stays visible and cannot earn change counts. These checks establish a comparison of captured source assertions, not independently adjudicated genuine semantic support.

The 30-day freshness window is an explicit versioned proposed policy, not a new BRD target. It is evaluated relative to each report's frozen analysis.as_of. The later source capture must advance beyond the earlier report's as_of; reused/cached earlier evidence is stale/not re-checked even if recently retrieved. No server wall clock makes a past comparison change each day. All displayed values remain historical, never labeled current availability.

- Changed: both sides have one eligible nonconflicting value, later evidence advances, and values differ. Equal eligible re-checks are unchanged. Changed wording/feedback means changed sampled source assertions, not proven changes in customer opinion or medical efficacy.
- Price: same brand/SKU/variant plus the same canonical listing context and unchanged currency, total purchase weight and pack quantity; normalization must already be eligible under B09. Missing identity/weight, ambiguous packs, currency changes or conflicting offers produce unknown comparisons and retain raw captured values. A real zero stays zero; no FX or inferred weight.
- New: a newly observed field/product identity in the later sample has eligible fresh evidence and the earlier selected brand had accessible fresh first-party capture. It is explicitly not a launch or proof of earlier catalogue absence. Failed earlier retrieval or an out-of-scope earlier brand cannot become a supported new-market claim.
- Gone: an already matched availability observation changes to one of the explicit accepted discontinued tokens, backed by a fresh first-party capture. The UI says source reports discontinued. OutOfStock is not discontinued; a newly observed discontinued SKU is not proof it disappeared between runs. No brand is inferred out of business.
- Unknown: missing observations, SKU, source, conflicting values, inaccessible/denied pages or out-of-scope selections. Failed-source URLs/status/dates are attached where available; the earlier value remains historical. An omission is never evidence of discontinuation.
- Stale: cached/nonadvancing evidence, stale captures, or unreconfirmed earlier observations whose age exceeds policy. Neither unknown nor stale increments gone or changed.

The extractor preserves optional explicitly advertised offer availability as an attributed source claim. Mismatched itemOffered and aggregate offers cannot supply that status. No availability is derived from HTTP failure, out-of-stock wording, absent HTML or a model guess. Existing recordings without this field retain their extraction outputs; the original workflow graph/version remains unchanged.

## UI and state behavior

Timeline marks both selections and shows true run creation dates/state, saved capture as_of, competitor count, version count and saved version. Defaults prefer an advancing captured date within the loaded category/geography cohort; the server still enforces customer/approval/time compatibility. Earlier/later run and version pickers are keyboard-native controls; paginated older reports remain discoverable. Draft versions are disabled for comparisons but have exact read links with approval state/date/hash. Counts show -- until a comparison succeeds, and changing any selector immediately hides old counts/results through an input fingerprint. Failed comparisons cannot leave a previous result visible; older in-flight comparisons are aborted when another starts.

Before/after cards show Earlier - historical and Later - captured evidence. Filters reveal unknown, stale and unchanged rows as well as supported changes. The default shows changes/gaps and leaves unchanged rows accessible through their filter. Evidence buttons group excerpts by stored source; dialogs preserve individual excerpts separated by rules, with their dates/URL/hash/locators, keyboard Escape and focus return. Source claims stay labeled as source_claim; no links or quote percentages become genuine-support scores.

At 390/768/1280px navigation wraps, controls and cards reflow, and hashes wrap. Competitor tiles/palette, forest/lime cover, timeline and paper/white before/after cards follow the HTML. Extra controls, qualification labels and source details deliberately increase page height. Screenshots are actual persisted DEMO captures, not an assertion of pixel identity or full accessibility certification. B10 captures remain unchanged; generic browser-regression captures now go to ignored cache and B11 captures live in docs/ui-screenshots/history.
